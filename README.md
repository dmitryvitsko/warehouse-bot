# 📦 Warehouse & Workflow Bot — Автоматизация склада и рабочих процессов

Специализированный Telegram-бот на Java, разработанный для комплексной автоматизации работы подразделений технической эксплуатации и бюро ремонта телекоммуникационных сетей.

## 📖 О проекте и его значимости

Традиционный учет кабельно-проводниковой продукции, расходных материалов и инструмента в линейных цехах связи часто опирается на бумажные журналы, разрозненные таблицы и устные договоренности. Это неизбежно приводит к потерям инструмента, путанице в единицах измерения (километры против метров), ошибкам в расчете НДС для абонентов и огромным временным затратам в конце каждого месяца при сдаче бухгалтерских отчетов.

**Warehouse Bot** полностью оцифровывает и решает эти проблемы. Бот превращает обычный мессенджер в полноценную мобильную ERP-систему (WMS) для материально ответственного лица (МОЛ) и карманный терминал сбора данных для каждого мастера. Проект не просто ведет учет, он выстраивает строгую и прозрачную дисциплину на предприятии, где каждое движение кабеля, розетки или пассатижей фиксируется в базе данных в реальном времени.

## 🚀 Сильные стороны и Преимущества

* **Доступность (Zero-installation):** Не требует установки сторонних приложений. Бот работает в Telegram, который уже есть на смартфоне у каждого сотрудника.
* **Сквозной контроль 24/7:** МОЛ в любую секунду видит сводку «У кого что на руках», предотвращая накопление излишков у линейных мастеров.
* **Умный UX для работы «в полях»:** Линейным инженерам некогда набирать длинные тексты на морозе или в подвале. Бот использует кнопки быстрого выбора (1, 2, 5, 10 шт.) и кликабельные текстовые команды (`/выдать_`, `/изъять_`), позволяя совершать массовые операции в пару тапов по экрану.
* **Устранение бухгалтерских ошибок:** Встроенный конвертер автоматически переводит «бухгалтерские» километры и тысячи штук в удобные для мастеров метры и единицы, а калькулятор сам начисляет +20% НДС для квитанций.
* **Защита от потери данных (ACID):** Использование транзакционной базы данных SQLite гарантирует, что если два мастера одновременно попытаются забрать со склада последнюю бухту кабеля, система обработает это корректно.

## 🎯 Основные решаемые задачи

* **Прозрачный баланс «Склад ↔ Мастер»:** Точный учет выдачи и списания материалов.
* **Синхронизация личностей:** Автоматическая привязка Telegram-аккаунтов к официальным фамилиям из графиков (Excel) — в отчетах фигурируют реальные ФИО, а не никнеймы.
* **Полный жизненный цикл инструмента:** Выдача, возврат, аудит, техническое списание (с указанием причины) и ведение архива инвентарных номеров.
* **Интерактивный график работ:** Загрузка расписания из Excel. Бот автоматически подсвечивает рабочие выходные (🟥) и дежурства (🚨), а также умеет показывать напарников по смене и старшего группы.
* **Плановые осмотры ОРШ:** Загрузка адресного плана, прием фотоотчетов от мастеров с автоматическим переименованием файлов в читаемый формат (`ОРШ 123 - Улица.jpg`) и отправкой на email руководству.

## ⚙️ Функциональные возможности по ролям

Доступ разделен на две роли с системой заявок: новый пользователь получает статус `PENDING`, пока администратор не одобрит доступ.

### 👷 Роль «Мастер» (WORKER)
* **📦 Склад и Подотчет:** Просмотр витрины склада (с ценами НДС), быстрое взятие материалов в подотчет, просмотр личного списка материалов и инструмента.
* **📝 Списание материалов:**
    * *По квитанции:* Ввод № квитанции, телефона, договора и адреса (FSM-диалог).
    * *Технический расход:* Выбор кода закрытия (212, 227 и др.), контроль ограничения на повторное использование кода 212 (не чаще 1 раза в 6 мес).
* **🧾 Калькулятор квитанции:** Добавление услуг из справочника и материалов из личного подотчета для расчета итоговой суммы к оплате.
* **📸 Осмотр ОРШ:** Выбор шкафа из списка, отправка фотоотчета или фиксация проблемы (затоплен, нет ключа).

### 👨‍💼 Роль «Администратор / МОЛ» (ADMIN)
Включает все возможности мастера, а также:
* **🚨 Система жесткого контроля:** Блокировка основного меню администратора при наличии необработанных заявок на регистрацию новых сотрудников или возвратов материалов (чтобы ни одна заявка не потерялась).
* **📥 Модуль импорта (Excel):** Загрузка 4 типов баз прямо в чат: Оборотная ведомость, База инструмента, График работ, План ОРШ.
* **🛠 Управление инструментом:** Массовая выдача через текстовые ссылки `/выдать_` (без закрытия меню), мгновенное изъятие `/изъять_`, просмотр сводного аудита (на складе / на руках).
* **📑 Отчетность и Аудит:** Генерация итогового месячного Excel-отчета и запуск массовой рассылки с напоминанием о сдаче подотчета.

## 📊 Структура генерируемого Excel-отчета (`Otchet_Sklad.xlsx`)

По запросу МОЛ бот формирует файл .xlsx, разделенный на 4 вкладки:

| Вкладка | Содержание | Назначение |
| :--- | :--- | :--- |
| **1. По квитанциям (Платные)** | Дата, ФИО, Код, Материал, Кол-во, Сумма с НДС, № Квитанции, Телефон заявки, № Договора, Адрес | Сверка платных нарядов и квитанций |
| **2. Без квитанций (Тех. расход)** | Дата, ФИО, Код, Материал, Кол-во, Телефон заявки, № Договора, Адрес, Код закрытия, Причина | Актирование списания по эксплуатации |
| **3. Сводная для бухгалтерии** | Суммарный расход по номенклатуре в рабочих (м, шт) и бухгалтерских (км, тыс. шт) единицах | Перенос итоговых цифр в бухгалтерию |
| **4. Остатки (Склад и Мастера)** | Детализация текущих остатков: склад МОЛ и сколько числится за каждым сотрудником | Инвентаризация на конец месяца |

## 🛠 Технологический стек и инструменты

* **Язык программирования:** Java (JDK 17+)
* **Система сборки:** Apache Maven
* **Telegram API:** TelegramBots (Long Polling Bot, Reply & Inline Keyboards, State Machine)
* **База данных:** SQLite (`sqlite-jdbc`)
* **Работа с документами Excel:** Apache POI (`poi-ooxml`)
* **Интеграция:** JavaMail API — отправка отчетов на почту.
* **Логирование:** SLF4J (`slf4j-simple`)

## 🗄 Архитектура проекта и базы данных

Проект имеет модульную структуру (`src/main/java`):
* `Main.java` — точка входа, инициализация БД.
* `WarehouseBot.java` — контроллер бота, маршрутизация команд, UI.
* `DatabaseManager.java` — слой работы с БД (DAO).
* `ExcelImporter.java` / `ExcelReportGenerator.java` — парсинг и генерация.

**Схема базы данных (`warehouse.db`) включает 9 таблиц:** `users`, `materials`, `employee_balances`, `tools`, `transactions`, `return_requests`, `service_tariffs`, `schedules` (+ `user_excel_names`), `orsh_inspections`.

## 🚀 Быстрый запуск и настройка

1. **Клонируйте репозиторий:**
   ```bash
   git clone [https://github.com/ВАШ_ЛОГИН/warehouse-bot.git](https://github.com/ВАШ_ЛОГИН/warehouse-bot.git)
   cd warehouse-bot

2. **Создайте файл конфигурации `config.properties` в корне проекта:**
   *(Файл добавлен в `.gitignore` в целях безопасности и не публикуется в репозитории)*
   ```properties
   bot.token=ВАШ_ТОКЕН_ОТ_BOTFATHER
   bot.username=ИМЯ_ВАШЕГО_БОТА
   ```

3. **Укажите свой Telegram ID администратора:**
   В классе `DatabaseManager.java` укажите ваш `ADMIN_ID`, чтобы бот автоматически предоставил вам права МОЛ.

4. **Соберите и запустите проект:**
   Запустите класс `Main.java` из IntelliJ IDEA или через консоль Maven:
   ```bash
   mvn compile exec:java -Dexec.mainClass="Main"
   ```
   При первом запуске база данных `warehouse.db` и все необходимые таблицы создадутся автоматически.
